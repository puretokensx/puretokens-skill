# Pure Tokens Skills repository rules

This repository owns the ten installable Skill instructions, model selections, contracts, documentation, validation, platform installers, and the small one-shot native API executor. It does not own, display, persist or manage user connection configuration or credentials.

## Git workflow

- Use `main` as the only development and release branch. Commit and publish directly from `main`; do not create feature, develop or release branches unless the user explicitly requests one.
- Keep version tags and published releases as release history. Complete the existing engineering and release checks before publishing from a pinned `main` commit.

## Direct API product contract

- API-facing Skills use full fixed URLs under `https://api.puretokensx.com`. Console-origin exceptions are the existing balance endpoints, the anonymous public model-group guidance endpoint and the opt-in completion receipt below. Fixed requests never reuse a configured Base URL as their target.
- The managed `puretokens-api` native executor performs every fixed request directly. It runs only for one command, exits after its receipt, and never opens a port, proxy, sidecar, background queue, or desktop UI.
- A credential adapter may read only the exact effective connection files documented for the active host. It first verifies that the configured endpoint is Pure Tokens, then uses one matching bearer credential only in memory for the fixed request. It must never scan a home directory, probe third-party configuration, use provider labels, or fall back to arbitrary environment variables.
- VS Code exception: within one verified native customendpoint group only, the executor may check inline Key equality in memory across model entries to establish a single connection. Never persist or report comparison data; different Keys, multiple matching groups or unsupported overrides stop. This does not identify the selected chat model.
- Switch CLI exception: CodeBuddy Code, Copilot CLI and Factory Droid may compare inline Keys only across the same host's endpoint-verified supported model/provider records. Qwen may compare its exact declared settings.env Key to the inherited same-name value; local Codex-backed Paseo requires its own saved profile and matching inherited endpoint/Key plus explicit PASEO_HOME. Comparisons only reject ambiguity or stale launch context; never substitute environment credentials, borrow another host's Key, persist comparison data or claim chat-model selection.
- Claude Desktop mapped-mode exception: Switch's existing Apply action writes a same-host `Claude-3p/puretokens-skills-connection.json` in the profile transaction. The executor may read that exact record only after verifying the active managed mapped profile and its byte hash, origin and private-file boundary. It never writes this record, reads Switch memory or borrows another host's Key. See `references/claude-mapped-connection.md`.
- Do not display, log, copy, persist, ask for, compare or report credentials, Base URLs, provider labels or host configuration. Do not add or require Node, npm, Python, MCP, a proxy, sidecar, separate upload service, or another authentication path.
- Computer Use, browser automation, desktop/mobile UI automation, and opening or clicking Pure Tokens Switch/Desktop are never API transports. Do not use them to submit a request, poll a task, retrieve media, or recover from an actual terminal/network failure.
- API-facing Skills must not invoke Imagen or another image/video Skill as a fallback. Never gate the fixed request on a separate “authenticated image/video interface” discovery step: use the active connection credential and issue the fixed API request through the current host's terminal or native HTTPS/API capability. Only an actual terminal, network, credential-resolution, attachment-byte, or API failure may produce the documented failure receipt.
- Core fixed API-origin endpoints are `/v1`, `/v1/models`, `/v1/media/models`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos`, and `/v1/videos/edits`, plus declared same-task status/content paths; dedicated evaluation, audio, embedding and rerank routes are declared below. Balance uses console-origin `/api/product/console/api-keys/usage` with the existing API key, then public `/api/product/console/status` without authentication. It requires no browser session. Never use legacy billing limits or unlimited-key placeholders as money.
- Optional operational completion reports use the separate anonymous fixed console-origin `/api/product/analytics/client-receipts` only when `PTP_OPERATIONS_RECEIPTS=1`. They have no credential, configuration read, persistent identifier, retries or queue and do not change business results; see `references/operations-receipts-contract.md`. This is not an additional inference/authentication transport.
- Jev evaluation adds fixed `POST /typesafe/v1/systemone`, a single synchronous request with a 90-second deadline and typed text-only `choice`/`score`/`noul` results. It has no media task ID, polling, retrieval or automatic retry. Explicit evaluation model discovery uses one `GET /v1/models`, intersected with reviewed exact IDs; visibility is not native-route acceptance. See `references/jev-evaluation-contract.md`.
- Audio adds fixed `POST /v1/audio/speech`, `/v1/audio/transcriptions` and `/v1/audio/generate`. One synchronous request has a 90-second deadline, with no task polling or retry. `audio-verify` only verifies an explicit local artifact before host handoff, without credentials or network. Explicit audio discovery intersects `GET /v1/models` with reviewed IDs. See `references/audio-execution-contract.md`.
- Embedding and rerank use fixed `POST /v1/embeddings` and `/v1/rerank`. Validate the bounded explicit text request and new absolute output file before credentials or networking. Each command is one synchronous 90-second request, without retry, polling, implicit file ingestion or database creation. Save ordered JSONL vectors or JSON ranking; accepted responses with unverified output retain billing uncertainty and never automatically resubmit. Explicit discovery intersects one `GET /v1/models` with reviewed exact IDs only. See `references/embedding-rerank-execution-contract.md`.
- StepFun music in `puretokens-audio` uses asynchronous `kind=music`: fixed `POST /v1/audio/music/submit`, then only `GET /v1/audio/music/tasks/{id}` and `/content`. Reuse task records and native MP3/WAV delivery (32 MiB), never synchronous `audio` or `audio-verify`. Gateway reads bind the account and original API key; records exclude prompt and lyrics. Explicit `music_v2_5` instead uses synchronous `audio` operation `music_sync` at `/v1/audio/generate`, with no task record or remote recovery; locally saved audio uses `audio-verify`. Never interchange these protocols.
- JSON and declared multipart requests are sent only by the native executor. Current user attachments are sent only with their declared operation; never upload, rehost, convert them to a text prompt, or silently downgrade a media-reference request.
- Gemini TTS and Lyria use separate asynchronous `kind=audio_task`: fixed `POST /v1/tasks/product-yutoux`, `GET /v1/tasks/{id}` and `/artifacts/audio/content`. Exact IDs and fields are declared in the audio contract. Verify the status platform and original ID; reuse task records and 32 MiB WAV/MP3 delivery without resubmission. Never route these models through StepFun music or synchronous audio.
- Exact reviewed Gemini image, Veo and Omni local references use `local_file_data_url`: the executor validates PNG/JPEG/WebP snapshots and encodes original bytes in memory into their existing JSON operation, preserving each role. Caller-provided data URLs and rehosting remain disallowed. Bound each file to 14 MiB and the full encoded body to 20 MiB.
- Exact GPT 2.6 JSON `masked_image_edit` uses 1-10 declared public HTTPS originals plus one local PNG mask, encoded only by the executor in memory; all-local multipart editing remains separate. Explicit image output formats must match verified native bytes through download and recovery. Preserve GIF bytes without conversion; attachment handoff does not prove animation playback. Separate video tail-frame delivery is limited to the four reviewed Super Vega Pro models and the artifact identity/recovery contract below; never infer it for another model.
- If an active host has no verified credential adapter, if policy blocks the executor, if attachment transport is unavailable, or if native byte delivery fails, stop with the documented safe receipt. Do not suggest a fallback transport.

## Skill behavior

- Image/video and StepFun music submissions are asynchronous. Submit once and immediately return the receipt before any wait or download; use separate status/wait/content commands, retain only the same returned task ID, and never automatically resubmit after uncertain output, status failure, timeout or delivery failure. Synchronous audio operations, including `music_sync`, make one POST with a 90-second deadline and no polling or automatic retry.
- Do not make `/v1/media/models` a preflight for ordinary core generation. Read only the selected profile for a default or exact model ID; use the small installed index only for selection or alias resolution; read the live catalog only for explicit discovery, an installed-profile gap, or post-rejection diagnosis.
- Exact-model restrictions in `runtime/executor/reviewed-media-policy.json` are shared by profile generation and the embedded executor. Apply them to discovery and new submissions even when installed profiles are absent or live declarations are stale; they never expand capabilities or restrict existing-task recovery.
- Normal wait-window exhaustion is successful pending, not a task failure. Preserve wait_windows_completed; at most two foreground windows per automatic delivery, then require explicit continuation. Errors, reconciliation and deferred retries stop automatic continuation; never resubmit.
- Treat physical dimensions as a request for guidance, not an API size value. Only declared model fields and values may be sent.
- Native bytes, not URLs, HTML, invented SVG, task IDs or status text, are required for successful delivery. Explicit GPT 2.6 SVG output uses the bounded static XML/CSS validator and original file attachment (8 MiB, complete HTTP 200 only); never execute or convert it.
- Explicit reviewed Super Vega Pro return_last_frame adds image artifact index 1 beside video index 0. requested_count stays 1; verify the original task artifact manifest, use the fixed last_frame content route, and track each proof/handoff independently. Never follow artifact URLs or resubmit for missing output.
- Six reviewed Kling IDs accept native_video at fixed /v1/videos with only bounded contents/settings/options. Validate roles, model-specific limits and existing resource IDs before networking; no flat/native mixing, cloning or resource creation. Realtime voice, voice cloning and subject/resource creation are out of scope. Audio translations require a verified exact-model protocol before exposure.
- The two exact Wan 3.0 IDs accept native_generation at fixed /v1/videos with bounded input.prompt/media and nested parameters. file/link means a supplied public HTTPS URL and requires explicit prompt_extend=true; never upload local files, mix flat/native inputs, persist the envelope or infer idempotency. See the installed Wan native guide.
- Preserve user-declared output units: existing resource lookup is not generation; one composed image is not a list of independent briefs. Explicit finite independent image generation uses separate prompts and task records, with actual delivery before the next submission. Never map different briefs to `n`, silently drop or combine items, or repeat delivered work after a later item stops. Keep these semantics aligned in the image entrypoint, contract and shared workflow guide.
- Keep every user-facing failure sanitized. Never expose raw responses, request data, internal URLs, stacks, upstream identities, credentials or user media.
- Model catalog receipts and published profiles follow `references/public-data-boundary.md` and the shared public projection policy. Unknown metadata must not pass through; new schema structure requires review without silently removing execution constraints. Public acceptance records omit private supplier associations and user-specific incident correlations. Legacy wire values remain explicit compatibility dependencies, not claimed privacy fixes.
- Image/video failures may offer compatible models only under `references/skill-fragments/model-alternatives.md`: use current-connection catalog evidence, preserve user requirements, and obtain explicit consent for one new potentially billable task. Unknown submissions, pending tasks, reconciliation and delivery failures retain same-task recovery; never switch models automatically or replace an existing task record. This does not authorize another transport or media Skill.
- Explicit model-group questions or confirmed model-permission rejection may use `model-groups`: one anonymous GET to fixed `https://console.puretokensx.com/api/product/docs/model-catalog`, a 20-second total budget, no credential/configuration reads, redirects or retries. Consume only exact-model `group_guidance` with live Switch display names; missing or conflicting data gives generic guidance, never guessed group names. Public membership is not account eligibility, current Key permission or model health. See `references/skill-fragments/model-groups.md`; users retain existing groups and apply changes themselves in Switch. This is not a generation preflight or an alternate authentication/inference path.

## Installation and updates

- Bootstrap downloads use the anonymous official GitHub Releases API, select one uploaded stable fetch asset by exact name, and verify its API URL, size and SHA-256 digest before execution. Fetch may reuse that invocation's metadata through --release-metadata / -ReleaseMetadata after checking its bound, stable asset identity and own bytes; this never replaces pre-execution verification. Without supplied metadata the browser route remains first; explicit HTTP 502/503/504 permits one same-release asset API GET. After that asset passes verification, reuse the API route for the remaining pinned assets without repeating failed browser requests. Cache metadata and route only within this invocation. Never fall back after permission, TLS, timeout, 401/403/404/429 or checksum failure, never require a GitHub token, and never retry the alternate request. This exception is installation-only, not permission to resubmit API tasks.

- The native fetch wrapper resolves the latest published stable release manifest, pins its version and source commit, verifies its selector and current-platform archive checksums, and delegates writes to Shell/PowerShell sync. Never fall back to main or a source archive during ordinary installation. Explicit local source sync remains available for maintainers. Installers synchronize the ten Skills and exactly one checksum-verified platform executor plus only the current system's managed fetch/sync scripts. They never install Node, npm, Python, a proxy, or a service.
- Same-version install/update may return without archive download, writes or init only after the selected release's executor checksum and all eleven local managed inventories verify. Modified, missing or unresolved transaction files stop the operation without automatic repair. Installation init uses one 20-second total budget for at most two read-only requests; a failed check does not undo successful installation.
- Updates synchronize only the ten current Skills and verified managed `.puretokens-executor`. Do not inspect or migrate retired plugins, Node runtimes or retired Skill names. Never delete unknown directories.
- Keep shared-root installations host-neutral: distribute one current-platform executor and the same self-contained Skills, never trim them to the last installed host. Generate the short host index and per-host execution/delivery references from maintained sources; read only the bound host on demand. Do not introduce per-client binaries or automatic cross-root links/migration.
- Preserve the exact first `text` install prompt under the required heading in both READMEs because the client download page extracts it.

## Validation

Use `npm run check` as the engineering gate and `npm run release:validate` as the release freshness gate. The engineering gate covers Go behavior and request/receipt schema conformance alongside repository checks. Node is permitted for repository development and validation only; it is never a user runtime dependency for media work.

- Credential adapter fixture coverage is not real-host end-to-end acceptance; record the latter separately.
- User output files are explicit artifacts, never a hidden cache. Download one index per invocation; reuse a validated same-task file in the same directory and attach it before requesting the next index.

- Help-only requests read the installed usage guide without init, doctor, credentials or network access. Explicit preflight never submits media; doctor never repairs or creates paid tasks; filtered models makes one catalog read. None is a normal-generation preflight.
- Optional absolute task records are user/workspace artifacts containing only task identity, original operation, count, safe parameters and progress. No prompt, credential, reference URL or media bytes. Resume never creates a task; mark delivered only after actual host attachment handoff.
- Mapped Claude media requires a task record with the writer's random `connection_id`; it is not an account ID or credential fingerprint. A changed/missing binding stops remote recovery without resubmission; verified local handoff remains available.
- Records may retain only reviewed terminal failure categories and optional public codes; missing legacy failure evidence stays unknown. Explicit `redeliver` uses the same task/index, verifies local content first, otherwise retrieves the same result without POST. Historical delivery remains intact; acknowledge the new handoff separately.
- Optional `timings_ms` measures exclusive local phases of this invocation only. It excludes agent work and host handoff, never enters task records or support/operations exports, and never causes extra requests. Offline agent trajectory checks and executor fixtures remain distinct from real-host acceptance.
- Exact price quotes, server idempotency and unknown-task lookup are not implemented here; do not infer them from local validation or task records.
