# 仅失败或消费问题时读取


失败答复应包含“本次发生了什么、任务是否已提交／是否保留原任务、下一步可以做什么”，将执行器 `next_action` 翻译成简洁自然语言。不要只给错误码或让用户自行排查。

## 按现象区分阶段

| 用户看到的现象 | 可以确认的证据 | 安全下一步 |
| --- | --- | --- |
| 安装完成，但连接未验证 | 文件同步成功与 init 结果分别报告 | 保留安装，不据 init 失败重装；用户明确要求时才在原 host 检查 |
| 能聊天，但 Skill 没有发请求 | 本地 `active_connection_*`／`workbuddy_*`／适配器不可用，且本次未调用 HTTP | 说明适配器无法确认当前连接，不断言未配置，不跨客户端探测 |
| 已提交但没有拿到 ID | `submission_outcome=unknown` 或提交回执丢失 | 停止，不能认定未扣费；不重提、不用请求 ID 猜任务 |
| 一直显示生成中 | `ok=true`、`wait_outcome=window_ended` | 保留原 ID 和窗口计数，最多两个自动前台窗口，之后明确续接 |
| 状态查询失败／需要对账 | 失败回执或 `reconciliation_required=true` | 停止自动续接；明确恢复时只处理原任务 |
| 已下载，但聊天中没有图片 | 下载回执存在，宿主附件尚未交付 | 只重交已验证文件，不重新生成；明确说明当前宿主交付限制 |

- `insufficient_quota`／`insufficient_balance`：明确提示本次可用额度／余额不足，提供 [Pure Tokens 官网 · 钱包充值](https://console.puretokensx.com/wallet)，引导用户登录查看钱包并按需充值。额度不足还应提醒检查当前 Key 限额，不能断言哪项耗尽或保证充值解决 Key 限额。不猜缺多少钱、实际扣费或充值后一定成功；用户要求时才查余额。此链接只供用户自行访问，不作为执行器请求或浏览器代查入口。
- 认证拒绝与权限不足分别解释，建议在宿主自身设置检查连接有效性或对应模型权限，不索取凭据、不自动更换连接。模型不存在时可建议明确查询模型；参数不支持时按所选 profile 修正字段并保留用户意图。
- 限流遵守回执中的等待要求；没有等待时间就不编造秒数。服务故障／网络失败只说明当前请求无法完成，不推断余额或凭据问题。内容拒绝请用户调整需求，不自动换模型绕过。
- 已有任务遇到状态／下载错误时保留原 ID、原操作及数量；终态失败不再轮询；下载成功但附件交付失败只处理已有文件，不能说已交付。记录或输出路径错误按脱敏建议检查访问权限／绝对路径，不删除未知文件。

优先使用执行器的阶段、`submission_outcome` 和脱敏说明。只有确认 POST 前的失败才能说未提交；网络或附件传输可能已经开始时，不能凭“附件失败”推断未创建任务。保留已知 task_id、`reconciliation_required`、`original_operation`、模型、已确认数量、安全参数及 `retry_not_before`；缺失数量表示未知，图片下载前必须确认原数量。未知提交不自动重试、不承诺未扣费或退款；状态／内容失败只继续原任务。

面向用户只说当前状态、产物或可操作的失败，不重复整份 JSON，不填“未返回”占位，不暴露内部 URL、原始响应、请求数据或配置。完整机器字段由执行器／可选任务记录保留。异常时才读 `behavior-scenarios.json` 匹配场景；详细约束在 `execution-contract.json`，简短展示规则在 `task-receipt.json`。

错误文字使用执行器的固定分类提示；只有服务端实际返回且执行器识别为公开分类的错误码才展示，未知码省略。不得根据被省略的原始错误猜测原因。文件结构校验失败或原输出损坏时，不把下载或文件复用说成成功；按回执继续获取同一任务索引。

用户明确要求试参数／检查请求时才用 `preflight --host <host-id> --request <文件>`；它不 POST，不创建任务，也不证明价格、余额或权限。普通生成不增加这一步。精确报价、服务端幂等提交和未知任务查找尚未提供；不能用本地校验或记录代替这些能力。

## 继续创作的选择

确认模型／能力拒绝或非对账终态失败后，按 [失败后的模型选择](model-alternatives.md) 提出有依据的兼容候选；
用户明确同意新任务及可能费用后才提交一次。该建议补充 next_action，不覆盖未知、原任务恢复、
权限／余额／限流或内容拒绝等停止条件，不声称某个模型当前全面不可用。

## 提供支持摘要

### 提交响应与版本

优先按 `local_error_code` 区分，不把以下情况都说成“服务器没有返回编号”：

| 本地分类 | 能确认的事实 | 建议表达 |
| --- | --- | --- |
| `task_response_unreadable` | 响应未能完整读取、解析为 JSON 对象或安全处理 | “提交响应无法读取，暂时无法确认任务编号。” |
| `task_id_missing` | 可解析的响应没有非空顶层 task_id／id；可能存在不符合契约的其他结构 | “响应中未找到约定位置的任务编号。” |
| `task_id_invalid` | 收到了编号字段，但类型或格式不符合执行器支持范围 | “客户端无法识别返回的任务编号。” |

三类提交回执均为 unknown：服务端可能已生成，不能断言生成失败、未扣费或应重新生成；不展示被拒绝的字段值。状态查询出现编号问题时则保留原任务，不把原任务降为未提交。不要从本地分类猜供应商、兼容版本或强制重装。

排障优先读取那位用户原回执的 `support.executor_version`；不能用维护者电脑、仓库版本或最新发布号代替实际运行版本。旧回执没有版本时，仅在用户要求检查时运行原客户端所加载执行器的 `--version`，该命令只读本地，不做 init／doctor 或新生成。用户明确要求更新后才进入 puretokens-update。

已知的编号兼容修复从 0.18.6 起支持小数点和历史冒号后缀；0.18.5 及更早版本的现象与原任务编号一致时才引用该结论，不把所有解析失败归为旧版。更新后新开会话，保留原任务；更新无法找回已丢弃的编号。已取得原公开任务编号时继续同任务查询／下载，不能为恢复任务手改记录或再次提交。

用户明确索取排障信息或决定联系私密支持时，只提取本次回执的 `support`，不粘贴整份回执、配置、原始日志、请求、提示词、参考地址或文件路径。不自动导出、上传、读取凭据或追加诊断；旧回执无摘要时不补造，不为了取得摘要重跑任务。

摘要仅含执行器版本、系统／架构、允许的宿主／命令、时间、本次状态和固定错误分类，及可用的任务 ID、最后一次 HTTP 尝试的阶段／状态码／网关请求 ID。`api_request_attempted=true` 只证明调用了 HTTP 客户端，不证明服务端收到、鉴权成功、任务已接受或扣费；false 只描述本次调用，不能推翻此前已提交的任务。

`request_id` 来自经过校验的 `X-Request-ID`（兼容旧 `X-Oneapi-Request-Id`），不使用供应商请求头；缺失、格式错误、重复或冲突时省略。它不是 task_id、幂等键或无 ID 任务找回接口，同一任务的提交、查询和下载可以各有不同请求 ID。已完成记录的本地恢复不回放旧网络证据。摘要仍含关联标识，只交给用户选择的私密支持，不放公开 issue。


官网入口只供用户自行访问，不运行浏览器或新增 API 请求；当前对话模型本身无法回复时由宿主处理。用户主动问消费记录或某次实际费用而结果无法确认时，提供 [使用记录](https://console.puretokensx.com/usage-logs)，不从余额差或任务状态推断扣费、退款或找回未知任务。

## 模型权限与分组

认证拒绝先按回执处理连接；明确模型权限拒绝或用户询问分组时，按 [线上分组指引](model-groups.md)
查询精确型号的公开归属。目录缺失不证明分组没选，服务故障不由换分组修复。
只有可靠回执才展示实时分组名；保留原分组、原任务及用户自行验证应用的边界，不自动重提。
