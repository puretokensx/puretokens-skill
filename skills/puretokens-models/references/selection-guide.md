# 按需求选模型

仅当用户明确需要选型比较、需求有歧义或提出“最好／最快／最便宜”时读取。
普通生成不先选型、不增加目录或余额检查。

1. 提取已有的必需条件：产物类型、是否编辑、附件角色和本地／公网输入、
   时长、尺寸／比例、数量等。用户已经给出的条件不重复询问，不为筛选将
   附件转存或把必需条件降为可选。只问会改变操作的缺失信息。
2. 对图片／视频，用原生 models 的现有筛选做一次目录读取。只把可表示的
   `kind/model/operation/parameters` 放进请求；“高质量”“便宜”等不是字段。
   本地附件角色须匹配声明的 multipart operation；公网引用按声明的 JSON
   字段核对，不套用只接受本地文件的 operation。目录筛选不验证附件字节。
3. 从该次回执列出所有满足必需条件的模型及匹配依据；同一次结果可以继续
   本地比较，不为改排版或解释再查。零结果说明“本次目录没有声明匹配项”；
   不推断用户无权限、模型下线或把不满足条件的模型推荐为替代。
4. 质量、速度、价格没有可信字段或可比实测时，明确这些项无法排序。
   可以继续展示已确认的兼容性差异，请用户按这些条件选择；不把默认模型、
   `pro/preview`名称、像素数或价格高低当成效果／速度排名。
   用户只问价格且没有需要查询的兼容性条件时直接说明报价能力缺口，
   不为这个问题调用不含价格的目录。
5. 比较完成不创建任务、不自动换模型。用户选定模型并明确生成后，
   交给对应Skill，保留原输入和条件；原任务恢复仍只用原模型与任务。

| 需求例子 | 可以确认 | 不能据此保证 |
| --- | --- | --- |
| 附件作首帧、5秒、720p | operation、时长／分辨率及组合限制 | 实际主体一致性、排队时长 |
| 一次三张同主题变体 | `n`及其与其他参数的约束 | 三份不同设计、准确收费 |
| 更便宜或更快 | 若没有权威报价／实测，仅列已声明兼容性差异 | 价格、平均延迟或质量排名 |
| 模型没出现在目录 | 这次未返回，或筛选条件未匹配 | 已退役、已被某模型替代 |

音频和Jev当前查询只确认审核ID在认证目录可见，不接受上述媒体参数筛选；
音色、操作和限制来自已安装审核profile，须标明该来源，不能冒充实时目录能力。
金额、退役日期、官方替代型号和速度／质量排名都要等网关发布相应契约及有效数据。
按已声明能力列出其他兼容候选不需要官方替代关系，但不能保证调用权限或服务健康；
原模型的一次失败也不证明下线。用户明确要求失败后查看候选时，仍只查一次当前连接的目录，
排除原失败 ID，保留全部必需条件；查到候选不提交任务，由对应媒体 Skill 取得新任务授权。

用户问某型号需要哪个分组时，单独按 [线上分组指引](model-groups.md) 查询线上公开归属；
此结果不能扩大认证目录候选，也不证明当前账户可选或 Key 可调用。
