# 失败后的模型选择（仅图片／视频）

仅在生成失败后需要给出继续创作的选择时读取；普通生成不增加目录、余额或诊断请求。
先保留原请求和已有任务，再根据执行器的阶段、状态、submission_outcome、公开错误分类及
reconciliation_required 判断下一步。推荐是对话建议，不是新提交授权，不改变 next_step。

## 先判断能否建议新任务

| 已确认的情况 | 下一步 |
| --- | --- |
| submission_outcome=rejected，明确为模型不存在或不支持所需能力／参数，且无任务 ID | 先核对精确 ID 和原模型声明；若确需其他模型，可按下节核对并提出候选，不自动提交 |
| 原任务确认为 failed／error／expired，且不需对账，也没有下列阻塞原因 | 保留原任务，说明本次失败；可提出兼容候选，等待用户确认创建新任务。不从失败状态猜全站故障或退款 |
| 用户取消、cancelled／canceled | 尊重取消，停止；不主动引导换模型继续消费 |
| 提交超时、5xx、响应丢失／编号异常、submission_outcome=unknown、状态查询失败或需要对账 | 先说明结果尚未确认，不主动给出换模型重做建议，不追加目录请求；有 ID 时优先按原回执恢复同任务 |
| 仍在生成、等待窗口用尽或 retry_deferred | 保留原任务并按回执续接；不能说模型不能用或建议换模型 |
| 已生成但下载／附件交付失败 | 只取原任务结果或重交已验证文件，不用另一个模型重做 |
| 本地执行／网络／附件能力受限、连接未识别、认证／权限／余额／额度／限流或内容拒绝 | 解释对应原因并按 next_action 处理；不将换模型当作修复或规避办法，不自动查询候选 |

阻塞原因和不确定性优先于 failed 等表面状态。原模型仅在本次请求失败，不能据此声称全面下线。
只在公开错误分类明确指向服务异常时说“可能暂时出现服务问题”；原因不明就说“本次生成失败”。
未知提交后，只有用户另行明确选择模型、理解原任务仍可能完成及重复消费风险，并确认新付费请求，
才按新任务处理；“继续”“再试试”不能代替该确认。需要对账的任务仍只按原任务处理。

## 候选必须有依据

1. 优先复用当前宿主、同一有效连接在本会话已返回且没有已知配置／分组变化的认证媒体目录。
   静态 index／profile 只说明已安装的适配能力，不证明当前 Key 权限或服务健康；不得借用其他
   客户端或公开未认证目录。跨会话、用户改过连接／分组或证据不明时，不沿用旧权限判断。
2. 明确的模型／参数／能力拒绝允许执行器做一次事后目录查询；其他失败没有当前目录依据时，
   先问用户是否查看兼容模型，明确同意后才查询一次。遵守现有 models 过滤契约，不把
   “同意查看候选”当作同意生成；查询失败或无匹配项就停止，不重试、不从静态清单补候选。
3. 只从认证目录返回的精确 ID 中选择当前需求兼容且执行器已支持的模型，排除本次失败的 ID。
   核对产物类型、generate／edit、附件角色、operation、传输、数量、比例／尺寸、时长、
   音轨及组合限制。目录过滤不能表达的附件数量／字节要求仍需核对；选定候选的本地 profile
   也必须支持这些字段。安装版本存在能力缺口时说明待适配，不手改 profile 或静默删参数。
4. 保留用户已表达的模型偏好；否则按匹配程度给出少量候选和具体依据，让用户选择。
   Nano Banana 只在它的某个精确型号通过上述核对时才可推荐，不写死 Image2 → Nano Banana。
   没有完全匹配项就说明差异，请用户决定是否调整要求；不删除参考图、不把首尾帧改成单帧，
   不把图生／编辑降为文生，也不擅自降低分辨率、时长或更改声音要求。
5. 这些是“可尝试的兼容候选”，不是官方替代型号或健康保证。目录可见不等于实际调用有权或
   必定成功；不编造更便宜、更快、更好、预计等待时间、精确费用、旧任务扣费或退款。

## 提议、确认、执行

用户指定的候选不在当前认证目录，或得到明确模型权限拒绝时，不把它说成模型服务坏了，
也不把公开目录里的型号补进可用候选。按 [线上分组指引](model-groups.md) 的触发条件
查询该精确型号的公开归属；分组名只取实时回执。配置后重新核对当前连接，继续保留
新任务确认及原任务恢复边界；权限、服务故障和目录缺失三者不能混为一谈。

提议时说清：本次实际状态、候选精确型号与匹配依据、需用户决定的参数变化，以及
“将创建新任务，可能产生费用”。保留用户创作要求、指定文案和仍可访问的原参考素材。

例如，已确认 Image2 本次失败且 nano-banana-2 满足当前需求时：
> Image2 这次未能完成生成。可以尝试 Nano Banana 2（nano-banana-2），保留你的创作要求和参考图片。是否用它创建一个新任务？新任务可能产生费用。

没有当前候选依据时：
> 这次生成失败，原因暂未确认。是否帮你查看当前连接中符合原要求的其他模型？查看不会提交生成。

- 用户对一个明确型号、已说明差异和费用边界的提议回答“可以／用它”，即授权一次新提交，
  不重复确认。列出多个候选或仍有关键能力差异时，先明确选择；模糊“继续”不默认换模型。
- 沿用原宿主及 Pure Tokens 原生执行器，按新模型声明组装请求；保留提示词、文案、附件字节
  和用途，仅映射语义一致且已声明的字段。不改客户端连接、默认模型、传输或其他 Skill。
- 新请求必须有独立的任务身份；使用记录时新建另一份明确的任务记录，保留旧记录和结果，
  不把新模型写进旧任务、不覆盖旧记录、不将旧 task_id 带入新 submit。
  提交一次，立即返回新回执，再按新任务 next_step 完成交付；不能把它说成原任务续接。
- 候选也失败就解释该次状态并停止自动流程；本次同意不授权继续轮换其他模型或重复提交。
  跨会话缺少提示词／素材时向用户补齐，不从任务记录猜内容或搜索无关文件。
