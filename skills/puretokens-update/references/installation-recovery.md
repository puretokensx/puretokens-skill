# 安装检查与明确修复

只用于用户主动要求检查或修复安装；普通生成不进入此流程。用户在当前任务已经明确要求修复即为授权，不再重复询问；仅检查安装不等于授权写入修复。始终保留当前宿主，不读取凭据或扫描其他客户端。

## 只读检查

安装版本支持此命令且本地执行器可以执行时，从 Skill 同级 `.puretokens-executor` 运行：

```text
<puretokens-api绝对路径> install-inspect --directory <十个Skill及.puretokens-executor所在根目录的绝对路径>
```

Windows 执行器名为 `puretokens-api.exe`。这里的目录是整个安装根，不是某一个 Skill，也不是 Home。命令只读十一个受管组件、安装根的事务条目，不读取认证、不发网络请求、不修改文件。

回执 `status=clean` 表示本地清单与当前文件一致，不证明来自某个发布版本、宿主已加载、连接可用或媒体交付成功。`attention_required` 的 findings 只含相对受管路径和固定错误码；不展示内容、绝对路径或完整日志。结果最多128项，`truncated=true` 时不能说已列出全部问题。

| category | 含义与下一步 |
| --- | --- |
| missing | 受管组件或文件缺失。可提议官方稳定版 repair；执行前需用户明确要求修复。 |
| modified | 受管文件被改写。保留定制，说明具体受管相对路径；repair 不会覆盖它。 |
| additional | 出现清单未记录的文件或目录，包括系统元数据。保留文件；不擅自删除或重建清单。 |
| transaction | 存在安装事务或锁。先确认没有仍在进行的安装；明确 repair 只恢复可验证的事务。 |
| unreadable | 清单不可读、缺失或格式不受支持，或遇到符号链接等不安全条目。不能推断文件内容安全，停止自动修复。 |

没有可执行的本地执行器时不借用另一客户端的执行器，不把 doctor 当作完整性检查。说明尚未完成检查；用户明确要求官方修复后，可使用已下载且可用的官方 fetch，或下载当前官方稳定版 fetch 到本地运行 repair。修复会先校验发布包，再用包内执行器检查目标。

## 用户明确要求修复后

```text
macOS/Linux: sh "<官方fetch绝对路径>" repair --host <当前宿主ID>
Windows: powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<官方fetch绝对路径>" repair -Host <当前宿主ID>
```

自定义安装仍须加原 `--target` / `-Target` 绝对目录，不能猜另一个目录。repair 固定当前稳定发布的版本、源码提交、选择器与平台包校验值，不回退 main、源码归档或镜像，不降级。它不是“强制覆盖”：只重建清单能证明归属且其余现存内容未改的缺失项，以及恢复经完整预检的受管事务。未知文件、改动、符号链接、未知事务内容和无法确认归属的目录都会停止并保留。

普通 install/update 发现缺失、改动、事务或同版校验失败仍停止，不自动转 repair。明确 repair 也不授权丢弃用户定制或任意删除备份；需另行处理明确冲突。修复成功后复用同步与自动 init 结果；连接验证失败不重修，生成任务不重提。
